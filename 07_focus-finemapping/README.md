# 07 — FOCUS Fine-mapping

TWAS fine-mapping with [ma-FOCUS](https://github.com/mancusolab/ma-focus):
take the per-(gene, tissue/cell-type) TWAS associations produced upstream,
fine-map each locus, and emit the per-(chromosome, tissue) significant-gene
lists consumed by `08_ptrs-construction/`.

> **Vendored ma-focus**: this step uses a lightly-modified copy of
> mancusolab/ma-focus at upstream `f3a38fd` (pyfocus v0.803), checked in
> under [`ma-focus-modified/`](ma-focus-modified/). The modification
> teaches `focus import` to accept the meta-analyzed bulk-tissue FUSION
> panels (`META_*`), whose `.wgt.RDat` files contain a single-column
> meta model with no `cv.performance` object and crash stock ma-focus.
> See `ma-focus-modified/README.md` for the rationale and exact change.

> [!TIP]
> **Reproducible demo (smoke test).** A committed fixture + runner exercise
> `focus import` + `focus finemap` end-to-end on public data:
> ```bash
> cd 07_focus-finemapping
> conda activate ma-focus            # env with the VENDORED ma-focus-modified installed
> export R_HOME="$CONDA_PREFIX/lib/R"  # same-arch R for rpy2 (see run_demo.sh header)
> ./run_demo.sh
> ```
> It fine-maps **1 GTEx tissue (Whole_Blood), chromosome 1, 12 genes** using real
> GTEx v8 FUSION weights + a 1000G-EUR chr1 LD window + the asthma meta-GWAS —
> all in [`sample_data/`](sample_data/) (~150 KB). The 90% credible set comes out
> as **SDF4 + TNFRSF18** (the two highest-|Z| genes), matching the committed
> reference. Uses the vendored [`ma-focus-modified/`](ma-focus-modified/), **not**
> stock ma-focus. See [`sample_data/README.md`](sample_data/README.md) and the
> `run_demo.sh` header for the exact env setup (the rpy2 `R_HOME` architecture
> requirement in particular).
>
> **Cell-type (OneK1K) track — pending.** The demo covers the tissue track only.
> The 17-cell-type track needs the OneK1K FUSION weight panels, which are not
> redistributable here; its committed `data/focus_credset_gene_tissue_17CT.tsv`
> still lets the downstream gene-list + figure steps run.

The pipeline runs in two parallel variants — one per feature set — that share
the same shape:

- **39 GTEx bulk tissues** — scripts without a suffix (`all_chr_focus.sh`,
  `Make_Pos_File_forWeights_expanse_v2.R`, `post_process.py`,
  `check_empty_focus_files.py`)
- **17 OneK1K cell types** — scripts with a `_17CT` suffix

Each variant has five stages:

1. **Split** the sorted TWAS-significant gene table by chromosome
   (`split_by_chr.sh`) so the SLURM driver can be launched as one job per
   chromosome.
2. **Per-(chr, gene) fine-mapping** (`all_chr_focus*.sh` + the matching
   `Make_Pos_File_forWeights_expanse_v2*.R`): for every focal gene, build a
   `.pos` file of all genes in ±1 Mb, import the FUSION weights as a FOCUS
   `.db`, run `focus finemap` against the per-chr meta-analysis sumstats and
   1000G EUR LD reference.
3. **QC** (`check_empty_focus_files*.py`): walk the results tree and list any
   empty / unreadable `.focus.tsv` files.
4. **Recovery** of OOM-killed finemap calls
   (`extract_focus_before_error.py` + `rerun_focus_failed.sh`): scrape
   `slurm-*.out` for `Unable to allocate` errors, capture the last
   `focus finemap` command before each failure, and replay them.
5. **Post-process + bridge to step 06**
   (`post_process*.py` → `process_focus_output_17CT.R`): combine every
   `.focus.tsv` into a single `focus_credset_gene_tissue_{39,17CT}.tsv` of
   credible-set genes, then explode that table into the per-(chr, tissue)
   gene-list files (`fdr_sig_genes_chr<chr>_<tissue>.txt`) that step 06's
   PTRS scoring consumes.

> **39-tissue → gene-list bridge.** Only the 17CT version of stage 5
> (`process_focus_output_17CT.R`) lives here. The 39-tissue `focus_geneList_39/`
> was generated by an ad-hoc adaptation of the same script and will be
> committed separately later.

## Environment setup

Uses the **vendored** [`ma-focus-modified/`](ma-focus-modified/) (pyfocus 0.803),
**not** stock ma-focus (which crashes on the `META_*` panels).

```bash
conda create -n ma-focus python=3.8 -y
conda activate ma-focus
pip install ./ma-focus-modified                 # vendored ma-FOCUS, version 0.803
pip install mygene 'rpy2==3.5.12'

# rpy2 loads FUSION *.wgt.RDat via R, so R_HOME must point at a SAME-ARCH R
# (e.g. an x86_64 conda R for x86_64 Python — a mismatched R silently imports 0 models):
conda install -n ma-focus r-base -y
export R_HOME="$CONDA_PREFIX/lib/R"

# the regional-plot / figure scripts also need:
pip install pandas numpy matplotlib
```

> [!IMPORTANT]
> The `R_HOME` architecture match is the most common setup pitfall — if
> `focus import` reports 0 models imported, your R and Python architectures
> differ. See `run_demo.sh` for the working invocation.

## Tissue vs CT: heritability keep-list handling

FOCUS itself applies no heritability filter at this stage — the filter is
**inherited via the sorted-gene table built upstream in `05_twas-analysis/`**.
Both tracks use the same logical filter (a per-feature heritability whitelist
that the upstream stage already intersected into the sorted-gene rows); the
only difference is the source of the whitelist:

- **Tissue (`sorted_gene_all39Tissue_new.csv`)** — every row in this table
  has already been intersected with the pre-given TCSC keep file
  `TranscriptsIn<Tissue>Model_keep.txt` by
  `05_twas-analysis/Make_sorted_gene_from_TWAS_results.R`.
- **CT (`sorted_gene_all17CT_new.csv`)** — every row has already been
  intersected with the inline-generated `twas_qc_genelist_ct.csv` by
  `05_twas-analysis/Make_sorted_gene_from_TWAS_results_ct.R`. The two
  whitelists are functionally equivalent (see the 05 README); only the
  source differs because OneK1K has no pre-given equivalent of TCSC's
  `_keep.txt` files.

Consequence: there is **no `_keep.txt` reference anywhere in this folder**
(neither in the `.sh` SLURM drivers nor in the `Make_Pos_File_*` helpers),
and no `twas_qc_genelist_ct.csv` reference either. If you change the
heritability filter, you change it upstream in 05 and re-run the pipeline
from there. See `05_twas-analysis/README.md` — *Tissue vs CT: heritability
keep-list handling* — for the upstream context.

## How to run

All scripts are pinned to absolute paths under
`${PROJECT_DIR}/FOCUS/`; either run from there or
edit the top-of-file paths before submitting.

### Stage 1 — split sorted-gene table

```bash
# Edit input_file / outdir at top to choose 17CT vs 39
sbatch split_by_chr.sh
```

Produces `chr_genes_17CT/chr<chr>_genes.csv` (17CT) or
`chr<chr>_genes.csv` in the FOCUS root (39).

### Stage 2 — per-chr fine-mapping (SLURM)

```bash
# 39 GTEx bulk tissues
for chr in {1..22}; do sbatch all_chr_focus.sh $chr; done

# 17 OneK1K cell types
for chr in {1..22}; do sbatch all_chr_focus_17CT.sh $chr; done
```

Each job activates the `ma-focus` conda env, processes every gene listed for
that chromosome, and emits `<results_dir>/<PANEL>/focus_result_<SYM>.focus.tsv`
(17CT) or `<results_dir>/<PANEL>/focus_result_<gene_id>.focus.tsv` (39). The
ma-focus environment is built from the vendored copy under
[`ma-focus-modified/`](ma-focus-modified/) (not upstream — stock ma-focus
crashes on our META_* panels):

```bash
conda create -n ma-focus python=3.8
conda activate ma-focus
cd 07_focus-finemapping/ma-focus-modified && pip install .
pip install mygene 'rpy2==3.5.12'
```

Memory-side guardrails matter: each driver pins
`OMP_NUM_THREADS=MKL_NUM_THREADS=OPENBLAS_NUM_THREADS=NUMEXPR_NUM_THREADS=1`
and `ulimit -v 128GiB`. Even so, OOM kills are common on dense loci — those
are recovered in stage 4.

### Stage 3 — QC

```bash
python check_empty_focus_files_17CT.py   # → empty_focus_files_17CT.txt, error_focus_files_17CT.txt
python check_empty_focus_files.py        # → empty_focus_files.txt,      error_focus_files.txt
```

### Stage 4 — recover OOM-killed finemaps

```bash
python extract_focus_before_error.py     # → focus_finemap_before_errors.txt (run from a dir with slurm-*.out)
sbatch rerun_focus_failed.sh             # replays captured commands; logs to rerun_logs/, failures to failed.list
```

### Stage 5 — post-process + build step-06 gene lists

```bash
# 5a: per-tissue .focus.tsv → single credible-set TSV
python post_process.py                   # → focus_credset_gene_tissue_39.tsv
python post_process_17CT.py              # → focus_credset_gene_tissue_17CT.tsv
python count_pip_no_credset.py           # PIP≥0.1 counts WITHOUT the credible-set filter (prints only)

# 5b: credible-set TSV → per-(chr, tissue) gene lists consumed by step 06
Rscript process_focus_output_17CT.R      # → focus_geneList_17CT/fdr_sig_genes_chr<chr>_<tissue>.txt
# (39-tissue equivalent is built separately for now; see note above.)
```

## Regional gene-level FOCUS plots (manuscript panels C–D)

`regional_focus_plot.py` draws a LocusZoom-style regional plot where **each dot
is a gene-model** (not a SNP): x = gene center (Mb), y = **FUSION marginal TWAS
Z** (the `.dat TWAS.Z`, supplied via `--fusion-dat-dir`; matched on Ensembl for
tissues / symbol for cell types — so the y-axis is the same statistic as the
Miami panels and the heatmap, *not* the FOCUS fine-mapping z), colour = FOCUS
PIP. A **red ring** marks every model of the focal gene (one per
tissue/cell-type — gene identity, *not* a credibility claim); a **black ring**
marks models in the FOCUS 90% credible set. A gene track underneath shows the
gene bodies in the window.

It runs in two decoupled stages so the plotted data is frozen and committed:

1. **build** — slice the focal gene's raw ma-FOCUS block to a window and write a
   tidy CSV (`data/panel_C_data.csv`, committed: 267 gene-models, 27 genes, 39
   tissues for the 17q21/GSDMB locus).
2. **plot** — render the figure from that CSV alone (no raw blocks needed).

### Panel C — GTEx tissues, 17q21 / GSDMB (committed)

```bash
# replot from the committed dataset (no raw FOCUS output required).
# --annotate-point adds a grey italic call-out on a specific gene x group dot
# (here: GSDMB in esophagus mucosa = Panel A's tissue, the strongest-Z but
# non-credible GSDMB model — illustrating high TWAS Z != high FOCUS PIP):
python regional_focus_plot.py --plot-only --csv data/panel_C_data.csv \
    --focal-ens ENSG00000073605 --focal-name GSDMB \
    --panel-letter C --group-label Tissues --window-mb 1 \
    --out figures/panel_C_17q21_tissues.png \
    --title 'C  17q21 asthma locus across GTEx tissues (1 Mb window)' \
    --annotate-point $'ENSG00000073605:esophagus_mucosa:GSDMB (esophagus mucosa)\nstrongest Z, not credible'

# rebuild the dataset from raw blocks (needs the per-block .focus.tsv on disk):
python regional_focus_plot.py --focus-dir <FOCUS_DIR> \
    --focal-ens ENSG00000073605 --focal-name GSDMB \
    --results-glob 'results/*/*.focus.tsv' \
    --annotation data/gene_annotation.txt.gz \
    --fusion-dat-dir <TWAS_RESULTS_DIR> \
    --panel-letter C --group-label Tissues --window-mb 1 \
    --csv data/panel_C_data.csv --out figures/panel_C_17q21_tissues.png
```

### Panel D — OneK1K cell types, HINT1 / cd4_naive (committed)

Same code, pointed at the raw cell-type blocks (`results_17CTnew/<cell_type>/
focus_result_<ENSG>_<cell_type>.focus.tsv`). The committed panel uses **HINT1**
(`ENSG00000169567`, 5q31.2) as the focal gene: it is in the **cd4_naive** FOCUS
credible set (TWAS Z = −5.5, PIP = 0.992) and fine-maps **decisively** over its
two window neighbours — CDC42SE2 and RAPGEF6 both stay at PIP < 0.01 in every
cell type. The committed dataset is 3 genes · 10 cell types · 16 gene-models ·
1 credible model. As in Panel C, every gene-model with a TWAS Z in the window is
plotted (not just credible-set genes); the window is sparser than the tissue
panel because OneK1K cell-type weights exist only for genes heritable *in that
cell type*.

> **Why HINT1?** GSDMB (Panel C focal gene) is absent from the cell-type FOCUS
> output, so Panel D needs a re-screened gene that is credible in a cell type.
> Screening all cd4_naive credible genes, HINT1 is the best balance of a
> *decisive* credible call (PIP 0.99) and a non-trivial neighbourhood (16
> gene-models across 10 cell types) — the cleanest winner-vs-neighbour contrast
> available. Note HINT1's TWAS Z is **cell-type-dependent**: negative in
> cd4_naive (the focal cell type, matching its Panel B position) but positive in
> b_naive / cd8_tcm — hence the focal-gene (red-ring) dots appear at both ±5.5 Z.

```bash
# replot from the committed dataset (no raw FOCUS output required):
python regional_focus_plot.py --plot-only --csv data/panel_D_data.csv \
    --focal-ens ENSG00000169567 --focal-name HINT1 \
    --panel-letter D --group-label 'Cell types' --window-mb 1 \
    --out figures/panel_D_celltypes.png \
    --title 'D  HINT1 locus across OneK1K cell types (1 Mb window)'

# rebuild the dataset from raw blocks on the server (needs the per-block .focus.tsv):
#   NOTE: the real results dir is results_17CTnew (not results_17CT), and because
#   --csv is joined under --focus-dir when focus-dir != '.', pass an ABSOLUTE --csv
#   (and --out / --annotation) so the files land in the repo, not under <FOCUS_DIR>.
python regional_focus_plot.py --focus-dir <FOCUS_DIR> \
    --focal-ens ENSG00000169567 --focal-name HINT1 \
    --results-glob 'results_17CTnew/*/*.focus.tsv' \
    --annotation "$PWD/data/gene_annotation.txt.gz" \
    --fusion-dat-dir <TWAS_RESULTS_CT_DIR> \
    --panel-letter D --group-label 'Cell types' --window-mb 1 \
    --csv "$PWD/data/panel_D_data.csv" --out "$PWD/figures/panel_D_celltypes.png" \
    --title 'D  HINT1 locus across OneK1K cell types (1 Mb window)'
```

To screen for a different cell-type focal gene, filter
`data/focus_credset_gene_tissue_17CT.tsv` to your cell type with
`in_cred_set_pop1 == 1`, rank by `pips_pop1`, and prefer a locus with several
tested neighbours in the ±0.5 Mb window.

**Note on interpretation:** fine-mapping is run *per tissue/cell-type*, so PIPs
sum to ~1 within each group and a high-PIP gene is in *that group's* credible
set. `in_cred_set == 1` alone is not sufficient — a group with no real TWAS
signal still yields a "90% credible set" of trivially low-PIP genes (the
normalization in `add_credible_set` divides by the group's total PIP mass).
Read PIP magnitude **and** credible-set membership together.

Requires: pandas, numpy, matplotlib (the `test`/ma-focus-style env).
